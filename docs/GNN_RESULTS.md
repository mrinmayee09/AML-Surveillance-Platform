# Reactive GNN - results on IBM AMLworld

_Generated by `python -m app.gnn.report_md` from the run reports. Do not edit by hand._

## Data and protocol

- **Dataset:** IBM AMLworld `HI-Small_Trans.csv` (Altman et al., NeurIPS 2023): 5,077,237 transfers between 515,088 accounts at 30,528 banks, 4,522 labelled laundering (0.089%).
- **Cut-off:** kept transfers up to 2022-09-10 (UTC); dropped 1108 later transfers, 655 of them laundering.
- **Split by time:** train 2022-08-31 → 2022-09-06 (6 days, 2,767,627 transfers, 1,999 laundering), val 2022-09-06 → 2022-09-08 (2 days, 964,862 transfers, 1,028 laundering), test 2022-09-08 → 2022-09-11 (3 days, 1,344,748 transfers, 1,495 laundering).
- **Task:** for each account active on a day, predict whether it sent or received a laundering transfer that day, from its 7-day, 3-hop neighbourhood (capped at 300 accounts).
- **Sampling:** all positive accounts kept; negatives sampled (1% train, 2% val/test) and re-weighted, so precision, PR-AUC and alert rate estimate the result on *all* active accounts.
- **Windows:** train 16,347 (3,171 positive), val 10,519 (1,602 positive), test 16,637 (2,359 positive).
- **Training:** AdamW, up to 30 epochs, early stopping on validation PR-AUC (patience 5) after a 10-epoch warm-up, so a slow-starting run is not cut off before it learns.
- **Thresholds** chosen on validation (max F1), applied unchanged to test. **5 seed(s)** per stochastic model (mean ± std).
